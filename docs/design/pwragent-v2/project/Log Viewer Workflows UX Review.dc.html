Logs: a window for finding lines and handing them to someone

People open Logs to find what went wrong, and then to send the evidence to someone else, often an Agent thread. Today the window makes both jobs harder than they should be. Search highlights matches but does not hide anything. Long lines are cut off at the edge, with no way to wrap them. Copying a line gives almost no feedback, and copying more than one line depends on a text drag that is hard to find. The build and instance details that make a log excerpt useful are a separate copy from another window. This review shows the window as built, the proposed window, and the five tasks it has to support. All fixture data is contrived.

Findings

#As builtChange
1Search only highlights. Typing fe leaves all 1,204 lines in place and marks 70 fragments. You page through them with Prev and Next. To answer “which lines mention this server”, you read the whole log.Search filters by default: only matching lines stay, and gaps show how many lines are hidden. Highlight is the other mode, for reading a match in place. A Context setting keeps 1, 3 or 5 lines around each match. The count reports lines, not fragments: 4 lines.
2Long lines are cut off. Lines use white-space: pre inside a max-content block, so every line is one row and the rest scrolls off to the right. There is no wrap setting, so there is nothing to keep turned on.A Wrap toggle in the toolbar, on by default and remembered in the profile. A wrapped line keeps its line number and indents its continuation rows so a new entry is easy to see.
3Row copy gives almost no feedback. The copy button appears only while the pointer is over the gutter. After a click, a 12 px check replaces it for 1.4 s and the pointer is usually covering it. The row does not change and nothing is announced.Every copy, one line or many, goes through the selection bar. The bar’s button changes to Copied, the copied rows flash, and the status bar reports what went to the clipboard, which is also announced to screen readers.
4Selecting several lines is hard to find. The gutter has user-select: none, so a drag that starts on the line numbers selects nothing. A drag through the text selects parts of lines and also pauses the stream without saying so.Line-number selection, as in a code editor. Click a number to select its line, Shift-click to extend the selection, or drag down the numbers. ⌘A selects every line shown and ⌘C copies the selection. Selecting text in a line still works.
5Diagnostics are a separate copy. The build, profile, PIDs and instance are in Help → Copy Diagnostics Info, and that menu item copies from the main window, not from Logs.An Include diagnostics checkbox in the selection bar, remembered. When it is on, the clipboard starts with the same troubleshooting block that Copy Diagnostics Info writes, plus the instance reference and the line range.
6Paused drops lines. While paused, onAppLogEntry ignores new entries until you resume and the snapshot is read again. The only sign of the pause is the text Paused app log stream.Pausing keeps buffering. The Live button changes to Paused, and a 37 new lines pill above the bottom edge jumps to the latest line and resumes.
7The file row takes a full band. The path, Copy and Reveal are used once per bug report, but they sit above the lines on every screen.The path, Copy path and Reveal move into a 34 px status bar under the lines. The status bar also shows the line count and the copy confirmation.
8Line numbers fail contrast (As Built, 2026-09-01): --text-subtle measures 2.65:1 in light.Line numbers use --text-muted. They are now controls, so they also need a hover state.

Workflow A — Find what just went wrong user · developer

Something failed a moment ago. Type part of the message. Filter mode keeps the matching lines, and Context keeps one line on each side so the cause is still visible. Here the cause is line 218, the app-server’s own stderr. Enter and Shift-Enter step through the matches.

  1. Press ⌘F and type startup failed. The view filters as you type and stops following.
  2. Set Context ±1 to keep a line around each match. 4 lines match, and the gaps show what was hidden.
  3. Clear the search with Esc and the window returns to the active match’s position in the full log.

Workflow B — Copy lines for a bug report user · developer

This is the task the window exists for. Select lines from the line numbers, leave Include diagnostics on, and copy. The clipboard then holds everything the reader needs in one paste. The checkbox keeps its setting between sessions.

  1. Click line number 215. The line is selected and the bar appears.
  2. Shift-click 219, or drag down the numbers. The bar reports 5 lines.
  3. Click Copy or press ⌘C. Esc or the × clears the selection.
  4. The rows flash, the button reads Copied for 2 s, and the status bar keeps the result until the next action.

Workflow C — Reproduce, then capture only the new lines developer

When you are about to reproduce a bug, click Mark. A divider with the time goes into the view, but not into the file. After the bug happens, Select since mark selects every line after the divider, and the selection bar copies them in the usual way. You do not need to scroll back or guess where the bug started.

Rules

PartRule
ToolbarOne row: search, Filter or Highlight, Context (Filter with a query only), levels, then Wrap, Mark, Live. Prev and Next move into the search field as chevrons beside the count. Below about 900 px, Wrap and Mark drop their labels and keep tooltips.
SearchCase-insensitive substring, as today. Filter keeps matching lines; Highlight keeps every line. Context 0, 1, 3 or 5 lines. A gap row says how many lines are hidden; click it to show them. The count reports matching lines, and the current one is n of N. Enter, Shift-Enter and Esc work while the field has focus.
Tokensscope: and thread:, created by clicking a scope or a threadId= value in a line, or by typing the prefix. Backspace in an empty field removes the last token.
LevelsUnchanged behaviour, including Debug turning on debug collection. Error and Warning show the count of loaded lines at that level, in mono 10.5 px.
WrapOn by default. Wrapped rows use pre-wrap and overflow-wrap: anywhere, with a 2ch hanging indent. Off restores today’s horizontal scroll.
SelectionLine numbers are the selection gutter: click, Shift-click, drag, ⌘A for every shown line, Esc to clear. Selected rows tint with --accent at 10% and get a 3 px accent edge on the number. The bar floats 14 px above the bottom of the viewport. With one line selected it reads Line 215.
CopyThe Copy button and ⌘C both copy whole lines in order, joined with newlines, via copyTextAsCodeBlock. If a text selection lies inside a single line, ⌘C copies that text as it does now. Feedback: the button changes to Copied for 2 s, the rows tint with --success-soft and fade over 600 ms, and an aria-live message in the status bar stays until the next action.
DiagnosticsInclude diagnostics starts on. When it is on, the copy begins with buildTroubleshootingDiagnosticsInfo, then the instance reference when federation is configured, then the line range and active filters, then a blank line.
MarkA mark exists only in the view, at the newest line when you click it, labelled with the time. A mark in the view offers Select since mark. A new mark replaces the old one. Marks are not written to the log file.
Live / PausedScrolling up or pressing the button pauses the view. While paused, new entries are buffered, up to the 5,000-line cap. The pill shows the new line count and any new errors. Selecting lines does not pause the view.
RememberedWrap, Filter or Highlight, Context, Include diagnostics, and the Error, Warning and Info levels are stored in the profile’s config.toml under [logs]. Debug is not stored, because turning it on starts debug collection.
Status barLine count, file name (full path in the tooltip), Copy path and Reveal, plus the copy and pause messages. It replaces the File row and the status line.
10

Left alone on purpose

  • aNo per-row copy button. One button per row cannot copy a range or include diagnostics, and it is where the missing feedback came from. Click a line number and press Copy.
  • bNo regex or query language. Plain text and two token kinds cover the tasks above. Developers who need more can open the file with Reveal.
  • cNo time-range picker. The view holds at most 5,000 lines, and Mark covers the task a time range would serve.
  • dNo structured field view. Wrapped lines already show key=value pairs in full. Parsing them into columns would fail on the free-form lines that most errors produce.
