Nothing moves. Every mark still says exactly what it said: this thread has a turn running, in accent for here and neutral for a peer.

The parked position is not a new pose — it is frame 50% of the sweep the beam already plays: centred, at full opacity, with its glow. The operator who turns Reduce Motion on sees the animation they knew, held still.

This is the load-bearing comparison. Without motion, the only thing separating "running" from "not running" is the parked beam against an empty track — a saturated tint with a glow, sitting in the middle of a flat one. It has to survive at 16×6 px in both themes.

The empty track is not new work: .signal-count__dormant-scanner already ships as the zero-count stand-in, and the strips already draw it beside a non-zero count when nothing is working. Reduced motion simply makes that existing pair carry the whole distinction.

Why mid-travel — the one position that needs no new number

Travel is exactly track width minus beam width in both variants — that is why the sweep ends flush at the right edge. So translateX(calc(var(--thinking-scanner-travel) / 2)) centres the beam in both sizes, and in any variant added later, without measuring anything or introducing a third custom property.

The opacity comes along for free: the sweep's 50% frame is opacity: 1, its brightest. Parking there gives the strongest possible static read, which is precisely what a still mark needs.

Spec — one rule, no component change

app.cssbeside @keyframes pwragent-thinking-scanner-sweep
/* The sweep is the app's most-repeated motion: one beam per running
   turn, so a busy fleet paints eight or more 1800ms loops at once in
   peripheral vision. Under the preference the beam holds frame 50% of
   its own keyframes -- centred, full opacity, glow intact -- rather
   than stopping where it started.

   Held, not hidden. This mark is the ONLY thing on a thread row that
   says a turn is running, and its idle counterpart
   (.signal-count__dormant-scanner) is an empty track of the same
   size, so removing the beam would make "running" and "idle"
   identical. `translateX(travel / 2)` centres it in both variants
   because travel is defined as width - beam-width in each. */
@media (prefers-reduced-motion: reduce) {
  .thinking-scanner__beam {
    animation: none;
    opacity: 1;
    transform: translateX(calc(var(--thinking-scanner-travel) / 2));
  }
}

No React change. ThinkingScanner's mount-time startTime = 0 pin exists so every beam shares one epoch; a media query that never starts or restarts an animation under a live element leaves that invariant alone. Nothing branches on the preference in JS, so nothing re-renders when the OS setting flips.

The zero state is untouched. AttentionTurnScanner still swaps element types between the dormant span and a fresh ThinkingScanner, which is what keeps the epoch pin honest.
