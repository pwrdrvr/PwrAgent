02

Where the proposal was wrong

Three corrections, all found by building it. Worth recording, because each one reads plausible on the page it came from.

1 The radiogroup was the wrong pattern. The review proposed role="radiogroup" with roving tabIndex and arrow-key navigation. But a radiogroup's arrow keys move selection, and selecting here writes config and re-runs discovery probes — so arrowing down a five-candidate list would fire five config writes and five rounds of --version spawns. Shipped instead as buttons in a labelled group with aria-current on the live one: natural tab order, no accidental selection, and the selected row is not a control at all because there is nothing to activate. Verified with axe across wcag2a/aa, wcag21a/aa and wcag22aa in both themes: zero violations.
2 "Apple" is not a chip label, it is a platform. The review's chip vocabulary named the top level after macOS. The shipped label is System, because the same level has to carry a Windows OS-vendor signature too. The distinction that actually matters is preserved — System for an OS-vendor signature, Signed for a third-party one — which is exactly what collapsing both into "Signed" would have thrown away on the rows where it counts: Apple's /usr/bin/git sitting next to a Developer ID app.
3 "Re-check" was already broken, and the review did not notice. The button called a plain settings refresh, and git discovery is memoized for the process lifetime — so it re-rendered the same snapshot every time. It needed a real re-probe channel (settings:refresh-git-discovery), which selection also needs for the pane to show the new choice as live.
