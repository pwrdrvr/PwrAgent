Sheet 2 · Trigger → manual entry

Typing a DM ID builds an automation that never fires

Manual entry always saves conversationKind: "channel". On Slack, Mattermost, Feishu and Discord the matcher rejects a real DM against a channel-kind target, so the automation is silently inert. On Telegram and LINE a legacy heuristic recognises the raw user ID and it works. Same action, two outcomes, no feedback either way.

Before the fix

The Slack channel ID. In Slack, open the channel details and copy the ID at the bottom, or copy a message link and take the C... segment.

every message in D0481KQ9ZLA

D… is Slack's DM conversation ID and the hint's own “copy the ID at the bottom” hands it to you. Save succeeds. The automation never runs, and nothing on the screen ever says why.

Fixed on this branch
Surface kind

The Slack member ID of the person whose DMs should trigger this — open their profile and copy the member ID. Not the D... conversation ID.

every direct message from U03QW7ELB19

One switch decides the kind, so the saved snapshot carries recipientUserId and the matcher can agree with the form. Label, placeholder and hint all follow the switch, so the field asks for the identifier it will actually use — the sender's member ID, which is what the matcher compares. Switching the kind re-encodes what is already typed rather than clearing it.

Sheet 3 · Trigger → Discord

A picker that promised channels it could never list

PwrAgent authorizes Discord servers, not channels, so the settings snapshot has no channel list and the editor offered DMs and nothing else. Sheet 4 · Filters → preview

A history limit stated too late, in the wrong noun

The main process decides historySupported synchronously from the provider and the scope. The editor only learns it after the panel opens, and because the flag starts false the panel asserts “History is unavailable” for a frame before the answer arrives. It also calls the trigger source a “destination”, which is a different field later in the same form.

The scope refusals are the same on every provider, so they are stated under the button before opening. Whether the provider reads history is only known to the main process, so the panel states it once it answers, and says nothing until then instead of assuming “unavailable”.

An open preview now joins the adapter's observed set. Before, a preview of #alerts before saving showed nothing from the alert bot the automation was for.

Sheet 6 · Automations list → replay

The empty state now blames the wrong thing

listReplayCandidates gained two new refusals in this change: a trigger with a recipientUserId or a parentId. The copy underneath was written when the only refusal was the provider, and said so — which for a Slack DM trigger is simply false.

Before the fix — Slack DM trigger

Replay a recent message from the trigger conversation. The badge is the filter's live verdict — replaying a non-matching message is a way to test what the automation would do if the filter let it through.

This provider can't serve conversation history, so there is nothing to replay. Use “Preview live messages” in the editor to test against new traffic instead.

Slack does serve conversation history — this same automation would offer replay if its trigger were the #release-eng channel. It is the DM scope that this build cannot read, and the sentence sends the operator to check the wrong thing.

Fixed on this branch — one sentence per refusal

Contact DM trigger — PwrAgent can't read back a contact's direct messages, only a conversation's. Use “Preview live messages” in the editor to test against new traffic instead.

Thread or topic trigger — replay reads whole conversations, not a single thread or topic. Use “Preview live messages” in the editor to test against new traffic instead.

Provider without history — Telegram can't serve conversation history, so there is nothing to replay. Use “Preview live messages” in the editor to test against new traffic instead.

A response from an older build, or a schedule trigger — there is no recent history to replay for this trigger. Use “Preview live messages” in the editor to test against new traffic instead.

listReplayCandidates now returns an unsupportedReason beside supported, checked most-specific-first so a Slack DM reports the scope rather than the provider. The provider sentence names the provider, and the fourth sentence is the fallback for a response that carries no reason at all.
